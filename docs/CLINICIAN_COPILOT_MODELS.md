# Hulka clinician copilot: model and evidence provenance

## Models (not accredited medical devices)
- Google **MedGemma 1.5 4B**: official model card https://developers.google.com/health-ai-developer-foundations/medgemma/model-card ; multimodal medical-document research.
- Google **MedGemma 27B**: official model card https://developers.google.com/health-ai-developer-foundations/medgemma/model-card-v1 ; text-oriented medical language research.
- **MedSigLIP** is a proposed image-embedding research option, **not wired into the copilot**. See https://developers.google.com/health-ai-developer-foundations/medsiglip .

These are pretrained research foundations, **not clinically accredited Hulka diagnostic systems**. Hulka-specific evaluation and required approvals are outstanding. The model identifiers currently select a routing name only; the operator must deploy a legitimately licensed model serving adapter and verify weights, model versions and evaluation reports.

## Implemented
- Clinician-only application screen with consented patient identifier and task selection.
- Server role and patient consent verification, restricted task and model allowlists.
- Approved-host allowlist for the Hulka-controlled HTTPS inference gateway (environment `HULKA_APPROVED_MODEL_HOSTS`), with secrets `HULKA_MEDICAL_MODEL_ENDPOINT`, `HULKA_MEDICAL_MODEL_TOKEN`.
- Gateway path is fixed at `/v1/clinical-assist`; fail closed when not configured.
- No raw patient chart sent by the endpoint; clinician-entered text **could still contain personal data**, requiring provider data-processing controls.
- Model name and official model card shown in client, model invocation metadata audited without recording the question.
- Literature is not generated by the model. Only externally validated and approved evidence references should be submitted; the current Flutter screen supplies no literature references, so output explicitly states none were verified.
- No auto-diagnosis, prescribing or medical-record writes from model output.

## Gateway adapter contract
POST `/v1/clinical-assist`, Bearer secret, request: `{modelId, task, question, evidence, system, maxOutputTokens}`. Response: `{response, references?}`. The gateway must authenticate requests, pin model revisions, restrict outbound network, avoid retaining PHI, apply privacy policies and support test-only and review-only environments. The application disregards unverified model-generated references.
