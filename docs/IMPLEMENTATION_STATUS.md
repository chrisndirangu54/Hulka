# Hulka implementation status

## Implemented application workflows

Hulka now includes operational in-repository workflows for:

- Flutter Material 3 responsive application shell and Firebase authentication
- patient registration, sign-in, password recovery and notification-token registration
- editable health profile with allergies, conditions and optional demographic context
- longitudinal patient timeline and observation models with provenance
- scoped patient consent grants and revocation
- clinician consent-gated longitudinal-history retrieval with server-side auditing
- clinician consultation queue and prescription issuance
- patient telemedicine appointment requests and session-provider handoff
- verified healthcare organization/provider administration
- pharmacy inventory publishing by verified pharmacists
- prescription-to-inventory matching by generic medicine, strength and dose form
- transactional pharmacy stock reservation with substitution review boundary
- pharmacist order-status workflow
- laboratory result ingestion endpoint and patient laboratory-results view
- Apple HealthKit / Android Health Connect data ingestion service using the Flutter health package
- emergency health card editing
- caregiver access grants
- chronic disease, maternal, child-health and rehabilitation program enrollment
- insurance coverage records and fail-closed eligibility adapter
- patient-reported meal, activity, sleep, rehabilitation and wellbeing logs
- configurable preventive-care rule engine; it generates no clinical reminders until a reviewed rule pack is installed
- adverse-event reporting and medication-response temporal-signal modeling
- privacy-thresholded medication-reaction cohort analytics
- aggregate-only population metric access for verified researchers/hospital administrators
- AI gateway with deterministic emergency-language escalation and fail-closed provider behavior
- Firestore rules separating patient, clinician, pharmacist, laboratory, researcher and administrative privileges
- server-only audit-event writes
- Flutter tests and GitHub Actions CI for Flutter analysis/tests and TypeScript Cloud Functions builds

## Deployment configuration still required

Some capabilities cannot be made genuinely live from source code alone because they require deployment-specific credentials, contracts, certificates, institutional endpoints or mobile entitlements:

- Firebase project configuration generated by FlutterFire
- production video-call provider credentials/session-token service
- iOS HealthKit entitlement and usage descriptions
- Android Health Connect manifest permissions
- Garmin / Samsung partner API credentials if those direct connectors are enabled
- hospital FHIR / HL7 endpoints and OAuth credentials
- DICOM / PACS endpoints and access policy
- external laboratory interfaces
- external pharmacy inventory feeds
- insurer eligibility / claims APIs
- M-Pesa / card payment credentials
- e-prescription signing certificates where required
- medical terminology services
- production AI/model provider, medical retrieval corpus and clinical validation
- clinically reviewed preventive-care rule packs

Hulka fails closed where these dependencies are not configured. It must not fabricate patient measurements, pharmacy availability, clinical results, insurer eligibility, provider availability or AI clinical conclusions.
